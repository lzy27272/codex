## 1. 本次范围

本次冻结：

1. 集团总经理与集团CEO合并为同一个岗位身份。
2. 集团董事长在不获得管理后台权限的前提下，可以向集团总经理、集团副总经理交办任务。
3. 增加行政人事、行政人事主管两个岗位；二者直属集团总经理，集团副总经理为间接领导。
4. 延续集团总经理以下管理岗位的周/月计划、直属审批和批准后自动转任务能力。
5. 区域经理岗位冻结不用，后续实际需要时再单独输出设计。

不在本次范围：启用区域经理、董事长审批工作计划、董事长向其他岗位派任务、副总经理代理人事岗位计划审批、行政人事普通岗位提交周/月计划、AI自动审批、编码、迁移或部署。

## 2. 角色、岗位与兼容编码

角色用于授权，岗位用于任职、汇报和任务责任，二者继续分离。

| 业务身份 | 系统角色代码 | 岗位代码 | 类型与范围 | 冻结职责 |
|---|---|---|---|---|
| 集团董事长 | `GROUP_CHAIRMAN`（新增SYSTEM角色） | `GROUP_CHAIRMAN`（新增岗位） | 集团根组织、`TENANT`受控业务范围 | 查看全集团工作；仅向集团总经理/CEO、集团副总经理交办任务并验收本人交办任务；无管理后台权限 |
| 集团总经理（集团CEO） | `CEO`（沿用既有SYSTEM角色） | `GROUP_GENERAL_MANAGER`（新增唯一岗位） | 集团根组织、`GROUP_MANAGEMENT` | 同一个岗位身份；负责集团经营管理，审批直属下属计划 |
| 集团副总经理 | `GROUP_VICE_PRESIDENT`（沿用既有SYSTEM角色） | `GROUP_VICE_PRESIDENT`（沿用既有岗位） | 集团根组织、`GROUP_MANAGEMENT` | 提交本人计划；按显式组织授权管理下属；作为两个人事岗位的间接领导 |
| 行政人事主管 | `HR_ADMINISTRATION_SUPERVISOR`（新增SYSTEM角色） | `HR_ADMINISTRATION_SUPERVISOR`（新增管理岗位） | 集团根组织、集团行政人事岗位族 | 直属集团总经理；提交本人计划 |
| 行政人事 | `HR_ADMINISTRATION`（新增SYSTEM角色） | `HR_ADMINISTRATION`（新增普通岗位） | 集团根组织、集团行政人事岗位族 | 直属集团总经理；首期不属于管理岗计划提交范围 |

兼容规则：

- 集团总经理和集团CEO只有一个有效岗位任职。不得新增`GROUP_GENERAL_MANAGER`同义系统角色，也不得给同一身份同时叠加`CEO`与同义角色。
- `GROUP_GENERAL_MANAGER`岗位的默认岗位方案显式映射既有`CEO`角色。既有CEO角色权限、模板、投资、KPI和配置治理职责不因本次身份合并被静默删除。
- 现有CEO账号实施时需有真实员工、`GROUP_GENERAL_MANAGER`岗位和有效任职，用于直属关系、审批及任务参与人；账号级权限不能替代任职关系。
- 既有CEO的账号级授权范围继续保留，但与业务动作任职分开。总经理审批计划、验收任务或成为任务参与人时，必须显式选择并由服务端校验本人的有效`GROUP_GENERAL_MANAGER`任职；未选择、选择其他岗位或伪造任职均失败关闭。
- 董事长增加岗位是为了形成任务发起人和验收人的精确任职链，不代表授予管理后台权限。
- 集团副总经理继续沿用`GROUP_VICE_PRESIDENT`，只统一中文展示名，不创建`GROUP_DEPUTY_GENERAL_MANAGER`。
- 既有`GENERAL_MANAGER`仍表示店总，`ASSISTANT_GENERAL_MANAGER`仍表示店助。
- `HR_ADMINISTRATION`和`HR_ADMINISTRATION_SUPERVISOR`不得复用、别名或自动附带`HR_KPI_ADMIN`。后者是既有补充性高权限角色，需要时必须另行显式授权。
- 集团暂不启用区域经理：不新增`REGIONAL_MANAGER`，不创建相应任职和汇报路由。`OTA_OPERATION_MANAGER`仅表示OTA运营经理，既有代码和数据保留，但不得展示或兼容为区域经理。

## 3. 冻结组织与汇报关系

```text
集团董事长
└─ 集团总经理（集团CEO）
   ├─ 集团副总经理
   ├─ 行政人事主管
   └─ 行政人事

集团副总经理 ··· 行政人事主管 / 行政人事（间接领导）
```

冻结解释：

- 集团总经理任职的`manager_assignment_id`指向董事长任职。集团总经理不提交工作计划，因此这条直属关系不产生董事长计划审批。
- 集团副总经理的`manager_assignment_id`指向集团总经理任职。
- 行政人事主管和行政人事的`manager_assignment_id`都直接指向集团总经理任职。系统不得根据“主管”二字把行政人事自动改挂到行政人事主管。
- “集团副总经理为间接领导”使用独立的有效任职关系表达，关系类型为`INDIRECT_LEADER`；不得写入或覆盖`manager_assignment_id`。
- 首期间接领导只允许在授权组织范围内查看和督导两个人事岗位的工作、计划与任务进度；不允许审批其计划、验收计划生成任务、代理直属主管或自动获得任务派发权。
- 若有多位副总经理，必须把具体副总任职与具体人事任职显式关联，不能按角色代码把所有副总自动扩成间接领导。
- 其他岗位的直属关系继续按有效任职显式配置；主管缺失时失败关闭，不按角色名、级别、组织祖先或区域经理层级自动猜测。
- 直属和间接关系均须同租户、有效期重叠、禁止自指和成环，并保留变更审计。

## 4. 区域经理冻结状态

- 当前状态固定为`DEFERRED / NOT IN USE`。
- 本需求不创建区域经理角色、岗位、任职、默认权限、导航、数据范围或审批路由。
- 现有OTA运营经理不是区域经理，不承担区域经理的兼容职责。

## 5. 工作计划适用范围

“集团总经理以下的所有管理岗位”冻结为：

- 集团总经理（集团CEO）本人不提交计划。
- 集团副总经理和所有在已发布岗位方案中显式获得`work-plan.submit`的管理岗位提交周/月计划。
- 行政人事主管是管理岗位，纳入计划；其直属审批人是集团总经理任职。
- 行政人事是普通岗位，首期不自动获得`work-plan.submit`。
- 董事长不提交、不查看待审批队列、不审批工作计划。
- 一线和其他非管理岗位不得因处于集团总经理组织树下自动获得计划权限。

V1.1默认管理岗位代码集合为：

- `GROUP_VICE_PRESIDENT`。
- `HR_ADMINISTRATION_SUPERVISOR`。
- `OTA_OPERATION_MANAGER`（仅按OTA运营经理本义）。
- `GENERAL_MANAGER`。
- `ASSISTANT_GENERAL_MANAGER`。
- `FRONT_OFFICE_SUPERVISOR`。
- `HOUSEKEEPING_SUPERVISOR`。

自定义管理岗位必须在已发布岗位方案中显式配置。已有人工编辑或减权方案不得由迁移静默覆盖；上线前必须形成差异清单并逐项发布。

## 6. 周期和计划内容

- 每份计划只属于一个租户、一个有效任职和一个周期，类型只有`WEEKLY`和`MONTHLY`。
- 周计划按租户时区的周一00:00至周日结束；月计划按自然月，保存周期起止和时区快照。
- 同一任职、计划类型、周期起始日只允许一个计划聚合；退回修改创建新修订，不创建第二份并行计划。
- 每项至少包含稳定项编号、标题、工作说明、优先级、计划完成时间和零至八个提醒时间。
- 提议完成时间必须晚于提交时间且位于周期内；最终完成时间必须晚于批准时间且仍位于周期内。
- 最终提醒必须晚于批准时间、早于最终完成时间且不重复。
- 计划只描述提交岗位自己的工作。审批通过后，每个计划项生成一个任务并分发回提交任职，直属主管成为验收人。

## 7. 提交、审批与修订

```text
DRAFT
  └─ SUBMIT → PENDING_APPROVAL
                    ├─ APPROVE_AND_DISPATCH → APPROVED
                    ├─ RETURN_AND_CREATE_REVISION → DRAFT
                    ├─ WITHDRAW_AND_CREATE_REVISION → DRAFT
                    └─ REJECT → REJECTED
```

- 提交时冻结计划修订、内容哈希、提交任职、直属主管任职和周期时区；提交后的修订不可原地修改。
- 主管逐项决定是否同意任务内容、完成时间和提醒设置；内容只能同意或退回，主管不得静默删除或改写。
- 只有全部内容同意，且全部完成时间和提醒形成合法最终值，才允许整单批准。
- 任一项不同意时整单退回，不部分批准、不创建任务。
- 退回或撤回在同一事务内封存旧修订并复制新的`DRAFT`修订；再次提交时重新解析当时的直属主管。
- 批准后的计划不可编辑；任务调整、返工和验收只走任务中心，不反写历史计划。

直属审批示例：

| 提交岗位 | 直属审批岗位 | 间接领导是否可审批 |
|---|---|---:|
| 集团副总经理 | 集团总经理（集团CEO） | 否 |
| 行政人事主管 | 集团总经理（集团CEO） | 否 |
| 其他管理岗位 | 其`manager_assignment_id`指向的有效管理任职 | 否 |

## 8. 计划批准后自动形成任务

批准和任务生成是一个不可拆分的业务命令：

1. 锁定计划和待审修订，校验版本、幂等键及精确直属主管任职。
2. 写入总决定和每项任务内容、完成时间、提醒决定。
3. 每个计划项创建并派发一个`management_task`到`PENDING_ACK`。
4. `ASSIGNEE`为提交任职，`REVIEWER`为审批任职。
5. 写入计划项—任务链接、提醒、审计和事务Outbox。

任一步失败全部回滚。任务幂等键固定为`work-plan:{planId}:{revisionId}:{itemId}`并按租户唯一。

## 9. 董事长受限任务交办

董事长交办是一条独立业务能力：

- 发起人必须是当前有效的`GROUP_CHAIRMAN`任职。
- 负责人只允许选择同租户、集团根组织下当前有效的`GROUP_GENERAL_MANAGER`或`GROUP_VICE_PRESIDENT`任职。
- 服务端必须按岗位代码和精确任职双重校验目标；目标下拉框、TENANT范围或通用`task.create/task.dispatch`都不能代替该校验。
- 一个命令原子创建任务、写入`ASSIGNEE`和`REVIEWER`并派发到`PENDING_ACK`；`REVIEWER`固定为发起交办的董事长任职。
- 董事长可以按字段最小化规则只读查看全集团任务；验收或退回只允许本人作为`REVIEWER`参与的交办任务。董事长不能执行负责人动作，也不能验收其他来源或其他董事长的任务。
- 任务来源固定为`CHAIRMAN_DIRECTIVE`，与`WORK_PLAN`来源分开；幂等键格式为`chairman-directive:{chairmanAssignmentId}:{clientCommandId}`。
- 首期不授予董事长取消、转派或修改已派发任务的能力。
- 董事长交办不改变任何人的`manager_assignment_id`，不形成工作计划审批权，也不允许向行政人事、行政人事主管、店总、OTA运营经理或其他岗位派发。

## 10. 权限冻结

| 能力 | 董事长 | 集团总经理/CEO | 集团副总及其他计划管理岗 | 行政人事 |
|---|---:|---:|---:|---:|
| 查看全集团业务工作 | 是 | 按既有CEO范围 | 按组织和任职范围 | 否 |
| `work-plan.read/submit` | 否 | 否 | 是 | 否 |
| `work-plan.team-read` | 是（全集团只读） | 是 | 按直属/间接授权查看 | 否 |
| `work-plan.review` | 否 | 是 | 仅精确直属下属 | 否 |
| `executive-task.read` | 全集团任务字段最小化只读 | 否 | 否 | 否 |
| `executive-task.assign` | 是（仅GM/副总） | 否 | 否 | 否 |
| `task.read` | 否（使用专用`executive-task.read`） | 按既有CEO范围 | 按组织、任职和参与人范围 | 仅本人参与任务 |
| `task.act` | 否 | 仅本人为`ASSIGNEE`的任务 | 仅本人为`ASSIGNEE`的任务 | 仅本人为`ASSIGNEE`的任务 |
| `task.review` | 仅本人为`REVIEWER`的`CHAIRMAN_DIRECTIVE` | 仅本人为`REVIEWER` | 仅本人为`REVIEWER` | 默认否 |
| 管理后台配置 | 否 | 保持既有CEO治理权限 | 本期不默认增加 | 否 |

安全规则：

- 董事长业务查看继续采用字段最小化的TENANT范围，排除薪酬、奖金、个人联系方式、凭证、密钥、完整审计导出等敏感字段。
- 董事长只通过专用`executive-task.read`字段最小化投影读取其他来源的集团任务，不获得通用`task.read`；除本人交办且本人为`REVIEWER`的任务外，所有执行、验收、退回、取消、转派或修改动作均拒绝。
- 董事长不授予`*`、IAM、组织维护、岗位方案、工作包、模板、规则、KPI、投资、企微、密钥、批量导出、`task.act`、通用`task.create/task.dispatch`或计划审批权限。
- `executive-task.assign`必须走后端专用目标策略，不能通过菜单隐藏实现。
- `task.review`始终要求当前董事长任职恰为目标任务的有效`REVIEWER`。
- 副总经理的间接领导关系只扩展经批准的团队只读查询；待审批查询始终只按冻结的直属主管任职返回。
- 通配权限也不能绕过精确直属审批、目标岗位白名单、任务参与人或跨租户限制。
- CEO账号级权限不得让系统忽略业务动作任职；同一CEO一人多岗时，只有显式选择的有效`GROUP_GENERAL_MANAGER`任职可以执行本冻结中的总经理审批和验收。
- 所有候选租户表必须强制RLS；所有动作还须校验组织范围、任职有效性和审计上下文。

## 11. 页面冻结

- 工作计划：我的计划、待我审批、下属计划和董事长集团计划只读视图。
- 待我审批只返回当前任职是冻结直属主管的计划；间接领导计划只出现在有权限的团队只读视图。
- 董事长任务中心增加“交办高管任务”，目标选择器只显示集团总经理（集团CEO）和集团副总经理有效任职。
- 董事长页面不显示全部功能、组织与权限、岗位配置、工作包配置、模板、规则、KPI、人事、投资、企微和系统配置入口。
- 工作计划批准生成任务与董事长交办任务必须显示不同来源标签。

## 12. 验收底线

- 不存在新增`GROUP_GENERAL_MANAGER`系统角色；`GROUP_GENERAL_MANAGER`岗位只映射既有`CEO`角色，同一身份不存在CEO与同义角色叠加。
- CEO既有账号级治理权限保持可用；未提供必填总经理业务任职时责任接口返回400，选择其他本人任职或伪造任职时返回403；只有选择本人有效`GROUP_GENERAL_MANAGER`任职时才可按参与人执行计划审批和任务验收。
- 董事长有精确岗位任职，但没有管理后台权限；其交办目标只有集团总经理和集团副总经理。
- 董事长向行政人事、行政人事主管、店总、OTA运营经理或其他岗位交办均返回403。
- 董事长可字段最小化只读查看全集团任务；对并非本人交办或本人不是`REVIEWER`的任务，所有动作均返回403。
- 董事长可验收或退回本人交办且本人为`REVIEWER`的任务，不能验收其他任务；重复命令只生成一条任务。
- 系统当前无区域经理角色、岗位、任职或路由；`OTA_OPERATION_MANAGER`不显示为区域经理，既有OTA数据不丢失。
- 行政人事和行政人事主管均直属集团总经理；副总经理可按显式间接关系查看，但审批两者计划均返回403。
- 行政人事主管可提交计划且只能由集团总经理任职审批；行政人事普通岗位提交计划返回403。
- 集团副总经理计划只能由集团总经理任职审批；董事长、其他副总、平台管理员均不能代审。
- 任一计划项不同意时不产生任务；全部同意时N项恰好产生N个任务，参与人、时间、提醒和来源准确。
- 无主管、无效主管、自我主管、循环、越权、跨租户或范围外关系全部失败关闭。
- 计划任务与董事长交办任务在来源、权限、列表、审计和幂等键上可区分，互不改变对方链路。
- 计划、任务、提醒、关系、审计和Outbox通过跨租户、跨组织及一人多岗负向测试。

## 13. 变更控制

以下变化必须先更新冻结并重新评审：

- 启用或创建区域经理。
- 拆分集团总经理和集团CEO，或新增同义角色。
- 董事长不设岗位却仍需成为任务验收人。
- 董事长扩大任务目标、取消/转派任务、审批计划或进入管理后台。
- 副总经理开始审批、代理或派发两个人事岗位的工作。
- 行政人事主管成为行政人事的直属领导，或行政人事普通岗位开始提交周/月计划。
- 主管解析不再以有效`manager_assignment_id`为唯一依据。
- 计划允许部分批准，或计划批准与任务生成不再原子、幂等。
