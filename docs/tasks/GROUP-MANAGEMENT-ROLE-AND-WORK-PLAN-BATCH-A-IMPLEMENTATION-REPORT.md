## 实施结果

- 身份链增加可空`businessActorAssignmentId`。首次身份请求不带任职时返回null与完整任职列表，前端随后默认主任职；显式选择仅接受当前账号在同租户的有效任职。CEO和平台管理员保留账号级权限与TENANT范围，并可独立选择业务动作任职。
- 增加稳定的业务任职错误码与`AccessPolicy`责任动作校验，避免把任职错误误报为JWT认证失败。
- 新增Flyway V39：3个SYSTEM角色、4个岗位、8项权限、11张强制RLS租户表、任务可信来源、直属/间接领导统一防环、状态/不可变约束和最小运行账号GRANT。
- 集团总经理岗位映射既有`CEO`角色；区域经理未新增，`OTA_OPERATION_MANAGER`未改义；迁移不创建任何真实人员任职或汇报关系。
- 三项能力开关默认关闭，只有布尔开关和UUID租户白名单同时满足才对租户生效；配置不安全时启动失败。
- Web统一使用服务端确认的业务任职发送`X-Assignment-Id`，CEO的账号级展示与业务任职选择分离；补充新岗位展示并删除错误泛化别名。
- Core API/Web候选版本为`0.2.0-pilot.8`，OpenAPI为`0.2.5-pilot.8`，API主版本仍为`/api/v1`。
